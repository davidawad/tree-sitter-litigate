# tree-sitter-litigate

A [tree-sitter](https://tree-sitter.github.io/tree-sitter/) grammar for
litigate: `.lit` rule modules and `.case` matters. litigate is a typed
language for encoding procedural-law rules and matters, with a compiler, a
language server (`litigate lsp --stdio`) and a manifest/lock pair
(`Lit.toml`, `Lit.lock`). The compiler lives in the litgraph repo; its
hand-written parser (`crates/litigate-syntax`) is the source of truth for
syntax, and when the two disagree this grammar is the one that is wrong.

This repo is the **grammar**, and nothing else. It exists separately because
three different consumers need it and none of them is a Vim plugin: the
[Helix](https://helix-editor.com/) editor fetches a grammar repo directly
from `languages.toml`, [nvim-treesitter](https://github.com/nvim-treesitter/nvim-treesitter)
does the same from a parser registry entry, and the Vim/Neovim plugin
[litigate.vim](https://github.com/davidawad/litigate.vim) builds a parser from
it at install time. A grammar-only consumer should not have to point at a
repo named after an editor, so this is named the way grammar repos are named
(`tree-sitter-<lang>`).

Editor support for litigate, by editor:

| editor | package | what you install |
| --- | --- | --- |
| Helix | [helix-litigate](https://github.com/davidawad/helix-litigate) (+ this grammar) | a `languages.toml` entry + the queries; `install.sh` does the rest |
| Neovim | [litigate.vim](https://github.com/davidawad/litigate.vim) (+ this grammar for the parser) | a vim-plug/lazy plugin; its build hook fetches this repo |
| Emacs 29+ | [litigate-mode.el](https://github.com/davidawad/litigate-mode.el) (+ this grammar for the parser) | an Emacs package built on `treesit`; `M-x litigate-mode-install-grammar` fetches this repo |
| anything else | **this repo** | compile `src/parser.c` + `src/scanner.c` |

## One grammar, two entry rules

Both file kinds use one grammar. The root `source_file` holds exactly one of:

- `lit_file`, which starts with `module`
- `case_file`, which starts with `case` (items in fixed order)

The first keyword decides which, so no dialect switch or file-extension
lookup is needed. Both kinds share references, records, literals and
expressions, and one set of queries covers both. `tree-sitter.json`
registers the `lit` and `case` file types.

The tree-sitter language name is `litigate`.

## How the grammar maps the language

- **Contextual keywords.** Every keyword is extracted from the `identifier`
  word token, so a word is a keyword only where the grammar expects one.
  `default`, `note`, `p` and the rest stay usable as names. Inside a node
  body, an item `Ident|_ String ->` is an edge. The field keywords and the
  edge clause keywords `by` and `p` are also valid edge ids there, aliased
  back to `identifier`. The `p "x" -> y` case is resolved by GLR
  (`conflicts: [[$.edge_decl]]`) because only the token after the keyword
  tells a clause from a new edge.
- **Citations.** `cite` is followed by `cite_text`, which the external
  scanner `src/scanner.c` lexes. It skips spaces and tabs and stops before a
  newline, `{`, `}`, `,`, or `//`. Trailing whitespace is excluded. A `cite`
  with nothing after it on its line is an error, as in the compiler.
- **Expressions.** Each precedence level is its own hidden rule, and every
  infix form surfaces as `binary_expression` with `left`, `operator` and
  `right` fields. Comparison is non-associative (`a < b < c` is an error).
  `match` may only head a whole expression.
- **Version requirements** (`^1.2.0`) are one `version_req` token, so trivia
  inside one is an error.
- **Leniency.** Number grouping (`1__0`), invalid dates (`2025-02-30`) and
  every semantic rule are compiler diagnostics, not tree-sitter errors.
  Unknown typed-literal suffixes (`1.eur`) are errors in both.

## Layout

| Path | What |
|---|---|
| `grammar.js` | root: word, extras, externals, conflicts, `source_file` |
| `grammar/lit.js`, `grammar/case.js`, `grammar/values.js` | `.lit` rules, `.case` rules, shared value/expression/token rules |
| `src/scanner.c` | external scanner for `cite_text` (hand-written) |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `tree-sitter generate`, committed on purpose |
| `queries/litigate/*.scm` | `highlights`, `locals`, `folds`, `indents`, `injections` (`injections.scm` is intentionally empty: doc comments and citations are prose) |
| `queries/*.scm` | symlinks into `queries/litigate/`, for tools that use the bare tree-sitter convention |
| `test/corpus/*.txt` | one corpus file per construct family, plus `errors.txt` for inputs that must not parse |
| `test/highlight/` | highlight assertions for a `.lit` and a `.case` sample |
| `examples/` | a real rule module, a real matter, and their manifest |

The committed parser is tree-sitter **ABI 15**. Editors linked against
libtree-sitter 0.25 or later load it as is. Older ones (Neovim 0.10/0.11,
Emacs built against an older libtree-sitter) need an ABI 14 parser:
`tree-sitter generate --abi 14` (needs node and `tree-sitter-cli`).
[litigate.vim](https://github.com/davidawad/litigate.vim)'s build script does
this for you.

## Install

### Helix

Helix has **no plugin system**, so support means a language entry, the query
files, and a build step. Use [helix-litigate](https://github.com/davidawad/helix-litigate),
which packages exactly that. The grammar entry it adds is:

```toml
[[grammar]]
name = "litigate"
source = { git = "https://github.com/davidawad/tree-sitter-litigate", rev = "<pin a commit>" }
```

Helix does not read queries out of a grammar repo, so the queries must be
copied into `~/.config/helix/runtime/queries/litigate/`; helix-litigate ships
Helix-flavoured copies (Helix names some captures differently).

### nvim-treesitter

On the `master` branch:

```lua
require('nvim-treesitter.parsers').get_parser_configs().litigate = {
  install_info = {
    url = 'https://github.com/davidawad/tree-sitter-litigate',
    files = { 'src/parser.c', 'src/scanner.c' },
    branch = 'main',
  },
  filetype = 'litigate',
}
```

then `:TSInstall litigate`. `src/scanner.c` must be listed: citations are
lexed there, so a parser built without it fails to link.
[litigate.vim](https://github.com/davidawad/litigate.vim) registers this for
both nvim-treesitter branches.

### Any other tree-sitter editor

```sh
tree-sitter generate                      # only if you edited grammar.js
mkdir -p parser
tree-sitter build -o parser/litigate.so
```

The output must be named `parser/litigate.so`: runtimepath-style consumers
search for `parser/<language>.so`. The `.so` is a build artifact and is
gitignored here.

## Testing / verification

```sh
tree-sitter generate                                   # src/ must not change
tree-sitter test                                       # 67 corpus parses + 2 highlight files
tree-sitter parse examples/rule12.lit examples/acme.case   # zero (ERROR) nodes
```

Verified against litgraph main (2026-10-23): all 123 files under `lit/`
(101 `.lit`) and `cases/` (22 `.case`) parse with zero `ERROR` or `MISSING`
nodes.

Those commands prove the **grammar**. They say nothing about whether a given
editor can *find* it, which is a different failure mode and every one of them
fails silently. If you are wiring a new consumer, assert resolution by name
before trusting anything visual:

```sh
nvim --clean --headless \
  --cmd 'set runtimepath+=<path to litigate.vim>' \
  -c 'lua print(vim.inspect(vim.api.nvim_get_runtime_file("parser/litigate.so", true)))' \
  -c 'lua print(vim.inspect(vim.treesitter.query.get_files("litigate", "highlights")))' \
  -c 'qall!'
```

Both must print a non-empty path list. A **headless** Neovim cannot prove
highlighting *renders*: it reports an active highlighter and applies zero
highlight extmarks, because highlighting happens on window redraw.

## Known limitations

- `injections.scm` is empty on purpose; nothing in a `.lit`/`.case` file is
  another language.
- Syntax the compiler rejects for semantic reasons (unknown names, duplicate
  ids, bad dates) parses cleanly here. That is by design: a grammar parses
  valid programs, the compiler reports the rest.
